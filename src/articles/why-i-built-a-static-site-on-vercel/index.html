我一直缺少一个真正适合发布长文的地方。社交媒体适合即时表达，却不适合安放那些需要被反复修改、长期保存、也希望能被搜索到的完整文章。过去，解决这个问题通常意味着先选择一套内容管理系统；但在 AI 时代，我决定反过来做：只保留静态网页，把内容管理交给 Agent。

于是有了这个网站。它不依赖庞大的后台，也没有一个需要我每天登录维护的编辑器。文章就是 HTML 文件，构建工具只负责把页面整理好，Vercel 负责让它们稳定地出现在互联网上。技术并不新，变化的是谁在帮助我使用这些技术。

以前，我们为什么需要 CMS

传统的内容管理系统解决过一组非常真实的问题。它给不写代码的人一个编辑器，替文章生成链接，把标题、日期、作者和分类放进数据库，再用模板输出页面。它还负责列表、翻页、搜索、图片上传和权限管理。一个网站只要开始持续更新，这些工作很快就会变得琐碎。

所以过去要做一个长文网站，我首先会想到 WordPress，或者另一套带后台的发布系统。表面上我是在写文章，实际上还要同时维护数据库、主题、插件、版本和服务器。系统把发布变得方便，也把很多与写作无关的复杂性留了下来。

如果一个网站有很多编辑、复杂权限和高频结构化内容，CMS 到今天仍然有价值。但对我这样的个人出版物而言，它解决的问题，正在被另一种工作方式重新分配。

AI 改变的不是页面，而是维护页面的方式

静态 HTML 一直很简单。真正让人退缩的，是每次发布都要复制文件、修改导航、处理图片、补充元数据，还要检查页面有没有写错。当文章越来越多，这些机械工作会累积成一套隐形的后台。

现在，这些事情可以交给 Agent。我要做的是把想法说出来，提供资料、图片和判断；Agent 可以把口述整理成长文，建立新的文章目录，写出语义清楚的 HTML，补齐描述、日期和结构化信息，再检查链接、图片尺寸、站点地图与页面输出。

过去需要一个系统来隐藏 HTML；现在我可以让 AI 直接管理 HTML。

这不是让 AI 代替我表达。文章写什么、删什么、最后是否成立，仍然由我判断。AI 接走的是重复劳动，以及过去只有熟悉网站工程的人才愿意处理的细节。

静态 HTML，再次成为合理的选择

静态页面有一种我很喜欢的诚实感。每一篇文章最终都是一个可以直接打开的文件，没有运行中的数据库，也不需要服务器在访问发生时临时拼装页面。浏览器拿到的就是文章本身。

它也很适合长期保存。HTML 是基础而成熟的网页格式，迁移时可以整体复制，版本变化可以在 Git 里追溯。搜索引擎看到的是完整正文，而不是等待脚本执行后才出现的一层界面。对一份以阅读为核心的个人出版物来说，这些朴素的特征比复杂功能更重要。

这个网站仍然使用 Node.js，但它只是构建时的助手：整理模板、生成文章列表、处理图片、输出 sitemap 和 RSS。部署完成之后，读者访问的依然是预先生成的 HTML、CSS 和图片。简单的技术，已经足以做出完整、快速而且有设计感的长文网站。

Publishing flow

从想法到页面

口述与资料 → Agent 整理初稿 → 我判断和修订 → 生成 HTML → 自动检查 → 预览 → 发布。

为什么先放在 Vercel

我需要的不是一台必须亲自照看的服务器，而是一个足够稳定、可以持续部署的网站入口。Vercel 与 Git 的工作方式很自然：内容更新后重新构建，成功的版本上线，出现问题也能回到之前的版本。HTTPS、分发和部署记录不需要我逐项维护。

它还给项目一个可以长期使用的默认域名。没有任何平台是永恒的，但在网站刚开始时，一个持续、清晰而且不必等待独立域名配置的地址很重要。它让我可以先开始写、先积累内容，而不是把时间消耗在搭建基础设施上。

Vercel 在中国大陆的访问并不总是理想，所以这个方案并不假设所有读者都从同一个入口访问。前期我会以海外部署为主；等内容与节奏稳定下来，再准备一套面向国内的部署。两个域名没有关系，只要内容来源一致，发布流程就仍然只有一套。

发布，变成一段持续的对话

以后我不需要先进入后台、新建文章、选择模板，再把各处内容搬进去。我可以直接在项目里说：我要写什么，哪些材料要引用，哪些图片要放进去。Agent 生成草稿，我检查；我说“发布”，它再完成验证和部署。

图片、漫画、视频和其他媒体也都可以跟文章放在一起。页面仍然是静态的，但内容并不因此单调。相反，越简单的底层越能把注意力留给版面、文字和叙事，而不是留给后台界面。

这也许是 AI 时代个人网站最有意思的变化：我们并没有发明一种新的网页格式，而是终于不必为了管理旧格式，背上一整套复杂系统。

我真正想建立的是出版节奏

这个网站不是一次性的作品集，也不是另一个需要运营的内容平台。它更像一本不断增加页码的出版物：每篇文章都有自己的地址，可以被链接、被搜索、被引用，也可以在几年之后继续修订。

技术方案最终应该退到后面。读者看到的是文字、图片和我的思考；我得到的，是一种可以一直写下去、写完就能发布的节奏。对现在的我来说，这比拥有一套功能齐全的 CMS 更重要。
