# MAI Unstoppable 长文站：整体方案

> 文档状态：规划基线 v0.3  
> 更新日期：2026-09-03  
> 当前阶段：视觉骨架已确认；进入网站工程与内容发布系统实施阶段

## 1. 项目定义

本项目是在 `mai-unstoppable` 当前工作目录内建立的独立网站子项目，用于发布可长期保存、可直接访问、可被传统搜索引擎和生成式搜索系统发现的长篇内容。

站点母品牌为：

- 中文：麥客不停
- 英文：MAI Unstoppable
- 品牌口号：麥客不停，创作不止 / Never stop creating.

它不是 4Lite 的附属网站。4Lite 是 MAI Unstoppable 的一个项目，可以在站内形成项目页、开发纪实专题和相关文章集合。

## 2. 已确认的核心决策

1. 网站位于当前项目内的 `website/` 子目录。
2. `website/` 是自包含、可独立构建和部署的项目，不直接发布父目录中的全部媒体资产。
3. 正文源文件以静态 HTML 为主，不以 Markdown 为内容载体。
4. 每篇文章构建后都是一个拥有独立 URL 的完整 HTML 页面。
5. 首个 HTTP 响应中必须包含完整正文，不依赖客户端 JavaScript 注入主要内容。
6. 海外站先行，Vercel 为第一阶段主部署平台。
7. 国内站后续使用另一个域名，部署到国内对象存储和 CDN。
8. 两套部署使用同一份内容与代码，但所有 HTML、图片、CSS、字体和脚本都各自完整部署，互不依赖。
9. SEO 和 GEO 属于第一版基础能力，不是上线后的附加优化。
10. 界面采用明亮暖白、清澈蓝黄和淡彩赛璐璐插画的当代出版物方向，详细规则见[视觉与排版设计](./VISUAL-DESIGN.md)。
11. 首页、文章列表、系列页、项目页、RSS 和 Sitemap 从内容集合自动生成；发布新文章不手工修改这些页面。
12. 每篇文章使用“HTML 正文 + 相邻元数据 + 同目录媒体”的独立文件夹，详细流程见[内容编写与发布规范](./CONTENT-AUTHORING.md)。
13. 文章原生支持图片、图集、视频、音频、交互嵌入、代码、表格和附件；任何媒体都必须有文本上下文与失败回退。
14. 站点级导航、媒体账号、作者和项目链接集中管理；YouTube 第一阶段保持关闭，不输出空链接。

## 3. 项目目标

### 3.1 内容目标

- 发布一人公司、人机协作、真实项目开发、创作方法和经营实践的深度内容。
- 支持普通长文、系列文章、项目纪实和多章节专题。
- 让内容脱离社交平台后仍然拥有稳定地址、完整上下文和长期价值。
- 让站内文章成为短视频、X Thread、公众号或其他平台内容的原始母版和引用来源。

### 3.2 发现目标

- 页面可被 Google、Bing 等传统搜索引擎抓取和收录。
- 后续国内镜像可针对百度等国内搜索引擎配置提交渠道。
- 页面可被 ChatGPT Search 等生成式搜索系统理解、检索和引用。
- 作者、品牌、项目、文章、发布日期、引用来源等信息具有机器可读结构。

### 3.3 工程目标

- 生成普通静态文件，可部署到 Vercel、OSS、COS、CDN 或任意静态服务器。
- 不依赖 Vercel Functions、专属图片服务或专属运行时。
- 禁用 JavaScript 后，正文、导航和主要信息仍然可用。
- 支持自动构建、质量检查、站点地图、RSS 和发布通知。
- 海外与国内部署故障相互隔离。

## 4. 非目标

第一版不包含以下内容：

- 用户注册和登录
- 在线富文本编辑器
- 数据库和动态后台
- 付费订阅系统
- 复杂评论系统
- 个性化推荐算法
- 依赖客户端渲染的单页应用
- 为追逐搜索排名而批量生成低价值页面

全文搜索、评论、邮件订阅和多语言可以在基础站点稳定后再评估。

## 5. 目标读者

第一阶段主要服务：

- 对 AI Agent 和人机协作感兴趣的实践者
- 独立开发者、一人公司经营者和创作者
- 关注真实开发过程、失败记录和方法论的人
- 从 X、YouTube、搜索引擎或项目页面进入的海外及跨境中文读者

站点部署以海外为主，不等同于第一阶段必须以英文为主。页面结构会预留多语言能力，但内容语言由具体文章决定。

## 6. 内容体系

### 6.1 内容类型

| 类型 | 用途 | 典型内容 |
| --- | --- | --- |
| 长文 | 单篇完整观点或经验 | Agent 使用经验、一人公司方法 |
| 系列 | 多篇按顺序组成的主题内容 | 人机协作实践系列 |
| 项目 | 项目背景、入口和相关内容聚合 | 4Lite 项目页 |
| 开发纪实 | 长周期项目的章节化记录 | 从记忆到校园 |
| 关于 | 品牌、作者和方法说明 | MAI Unstoppable、作者介绍 |

### 6.2 第一版信息架构

```text
/
├── /articles/
│   └── /articles/{slug}/
├── /series/
│   └── /series/{slug}/
├── /projects/
│   └── /projects/{slug}/
├── /about/
├── /feed.xml
├── /sitemap.xml
├── /robots.txt
└── /404.html
```

英文或其他语言路径在确有内容时再启用，避免生成只有导航、没有实质内容的空栏目。

## 7. 页面范围

### 7.1 首页

- 明确展示 MAI Unstoppable 品牌和内容定位。
- 展示一篇重点长文或重点专题。
- 展示最新文章、系列和项目。
- 提供作者、RSS、社交账号和地区镜像入口。

### 7.2 文章列表

- 按发布时间显示正式发布的文章。
- 支持标签和系列关系，但第一版不堆叠复杂筛选控件。
- 草稿和未到发布日期的内容不能进入列表。

### 7.3 文章页

- 标题、摘要、作者、发布时间、更新时间。
- 完整语义化 HTML 正文。
- 不显示文章大纲或内容目录；保留稳定章节锚点，供直接链接和搜索定位使用。
- 图片、图注、引用、旁注、代码和视频等内容组件。
- 上一篇、下一篇、所属系列和相关文章。
- 许可、修订记录和来源信息。

### 7.4 系列与专题页

- 说明系列主题、阅读顺序和当前进度。
- 支持已发布、待发布和更新中状态。
- 每个章节有独立 URL；如提供全文版，也要正确处理 canonical。

### 7.5 项目页

- 项目简介、状态、入口、代码或演示链接。
- 聚合与项目有关的长文、视频和其他公开内容。
- 4Lite 作为第一批项目之一接入，而不是改变网站母品牌。

### 7.6 关于页

- MAI Unstoppable 的名称、定位和创作理念。
- 作者身份及可验证的外部账号。
- 一人公司与 Agent 协作关系说明。
- 内容许可、联系方式和站点镜像说明。

## 8. SEO 基线

每个可收录页面必须具备：

- 唯一且准确的 `<title>`
- 唯一的页面摘要
- 一个明确的 `<h1>`
- 合理的标题层级
- 正确的 `lang`
- `canonical`
- `robots` 指令
- Open Graph 和分享卡片信息
- 正常的 `<a href>` 内部链接
- 描述性 URL
- 图片替代文本、尺寸和图注
- 正确的 HTTP 状态码
- 可在源代码中直接读取的正文

站点必须自动生成 Sitemap 和 RSS。正式发布后接入 Google Search Console、Bing Webmaster Tools，并在内容变更时提交 IndexNow。

搜索引擎收录和排名无法保证；项目目标是消除技术阻碍，并持续提供真实、有用、原创和可验证的内容。

## 9. GEO 基线

GEO 在本项目中指让生成式搜索和 AI 检索系统更容易理解、定位、摘录和引用内容。它不以关键词堆砌或面向机器改写全文为手段。

文章模板和编辑规范应支持：

- 开头的准确摘要
- 清晰的主题、结论和关键发现
- 稳定且描述性的章节标题与锚点
- 明确区分事实、个人经验、估算和推测
- 可追溯的引用、链接和访问日期
- 原始案例、过程记录、数据和截图
- 作者页、项目页和相关内容之间的实体关系
- 发布时间、更新时间和修订记录
- 图片说明和上下文，而不只是装饰图
- 机器可读的 Article、Person、Organization 和 Breadcrumb 数据

`llms.txt` 可以作为实验性导航文件自动生成，但不作为收录或引用的保证，也不替代 HTML、Sitemap、RSS、结构化数据和正常内部链接。

## 10. AI 爬虫原则

- 默认允许正常网页抓取。
- 明确允许 `OAI-SearchBot`，以支持 ChatGPT 搜索发现。
- 将搜索发现与模型训练授权分开处理。
- `GPTBot` 是否允许由站点所有者在上线前单独决定。
- 不使用登录墙、客户端渲染或反爬逻辑阻挡正式公开文章。
- 国内镜像上线时单独维护其 Sitemap、robots 和搜索平台验证文件。

## 11. 海外与国内部署

### 第一阶段：海外主站

- 使用海外正式域名。
- 部署到 Vercel。
- 海外域名是第一阶段 canonical 来源。
- RSS、Sitemap、分享卡片和作者链接使用正式域名。

### 第二阶段：国内镜像

- 使用独立国内域名。
- 部署到阿里云 OSS 或腾讯云 COS，并接入国内 CDN。
- 完整复制 HTML、CSS、JavaScript、字体和图片，不从海外站跨域加载关键资源。
- 根据备案和国内搜索收录目标确定最终 canonical 策略。
- 两套站点提供清晰的人工切换入口，不强制按 IP 重定向。

## 12. 发布流程

```text
编写 HTML 正文和文章元数据
        ↓
本地预览与内容检查
        ↓
构建完整静态站
        ↓
HTML / 链接 / 结构化数据 / 可访问性检查
        ↓
提交 Git
        ↓
Vercel 自动发布海外站
        ↓
更新 Sitemap、RSS、IndexNow
        ↓
国内镜像启用后并行发布国内静态产物
```

正式内容只有一个源版本，不手工维护海外和国内两份文章。

## 14. 第一版验收标准

- 禁用 JavaScript 后所有文章仍可完整阅读。
- 查看页面源代码即可找到标题、摘要、正文、作者和日期。
- 每个正式页面有唯一 URL、一个 H1 和一个 canonical。
- 正式页面返回 200，不存在的页面真实返回 404。
- JSON-LD 与页面可见信息一致。
- 草稿不进入列表、RSS 和 Sitemap。
- 不存在破损内链、缺失图片和重复输出路径。
- 页面可以在手机和桌面端舒适阅读。
- 海外构建产物不依赖 Vercel 专属运行时。
- 后续国内部署无需重写正文或页面结构。

## 15. 已确认的设计决策

- 首页采用以文字排版为核心的编辑出版物结构，不使用卡片堆叠。
- 首页与内页共用原色官方 Logo、统一站头和统一文字页脚。
- 页面使用固定明亮纸面，不制作自动深色模式。
- 全页控制为三个主要字号层级；层级主要依靠字重、行距、栏宽和留白。
- 文章使用单一阅读轴，不论长短都不显示内容大纲。
- 正文、头图和插图遵守同一版心，不使用任意出血。
- Hero 以淡彩或水彩背景承托文字，不要求频繁更换人物插画。
- YouTube 暂时不接入页脚；媒体账号由共享数据控制显示状态。
